# `internal/model`

GORM entities — the persistence shape of a domain, one file per entity
(`internal/model/<entity>.go`). Distinct from a module's DTOs (see
[modules.md](./modules.md)): a model describes what's stored, a DTO
describes what's accepted/returned over HTTP — they usually overlap but
aren't the same type, and a handler never returns a model straight from the
database without going through a service that owns that decision.

The skeleton ships no entities (`internal/model/doc.go` is just the package
declaration). The examples below are the shape the
[`create-backend-module` skill](../../.claude/skills/create-backend-module/SKILL.md)
produces.

## Shape

```go
type Widget struct {
    ID string `gorm:"type:uuid;primaryKey;default:gen_random_uuid()" json:"id"`

    Name string        `gorm:"type:varchar(255);not null" json:"name"`
    Spec jsonx.JSONMap `gorm:"type:jsonb;not null" json:"spec"`
}

func (Widget) TableName() string {
    return "widgets"
}
```

- **UUID primary keys**, generated by Postgres (`default:gen_random_uuid()`),
  not by the application.
- **`gorm` tags carry the real schema** (`type`, `not null`, `default`,
  `index`, foreign keys) — but they're documentation/query-building hints,
  not what creates the schema. That's the migration's job (schema and model
  tags must be kept in sync by hand — see [migrations.md](./migrations.md)).
- **`json` tags** control the API shape when a model is serialized directly
  (list/get responses, see [modules.md](./modules.md)). A field that must
  never leave the server (a password hash, a hashed API key) is tagged
  `json:"-"`.
- **`TableName()`** is only needed when GORM's default pluralization would
  guess wrong for the entity name.
- **JSONB columns** are typed `jsonx.JSONMap` (arbitrary JSON, see
  [`pkg/jsonx`](../../pkg/jsonx)) or, for a strongly-typed slice/struct,
  tagged `serializer:json`.

## Relationships

```go
type Post struct {
    ID string `gorm:"type:uuid;primaryKey;default:gen_random_uuid()" json:"id"`

    AuthorID string `gorm:"type:uuid;not null;index" json:"author_id"`

    Author   *Author   `gorm:"foreignKey:AuthorID;references:ID;constraint:OnDelete:CASCADE" json:"author"`
    Comments []Comment `gorm:"foreignKey:PostID;constraint:OnDelete:CASCADE" json:"comments"`
}
```

- The foreign-key **scalar column** (`AuthorID`) is what's normally selected
  and filtered on; it has its own `gorm:"index"` tag.
- The **association field** (`Author *Author`) is only populated when
  explicitly requested via `filter.Include("Author")` (see
  [filter-page.md](./filter-page.md)). Tag it `json:"-"` when a response
  must never carry it (most models do); a model that's only ever returned
  with its associations already loaded can name the field instead.
- `constraint:OnDelete:CASCADE` documents the FK's delete behavior — it
  must match what the migration actually declares.

## Model helpers for other layers

A model can carry small conversion methods when a value needs to cross into
another layer's shape (mapping fields into a client/response struct, say).
Keep these one-directional and thin (mapping fields, not business logic) —
real logic stays in `service.go`.
