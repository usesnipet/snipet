title: Apps

An app is a place where your agents are used: your website, your product, a customer portal. It decides who can chat and from where. Every conversation of an end user belongs to an app.

Create apps in **Apps**. Click an app to see its ID, where it runs and its API keys.

![App form](/images/docs/apps-form.png)

## Allowed origins

The sites that may use the app from a browser, like `https://app.example.com`. Requests from other origins are rejected. Left empty, any site is accepted, so only leave it empty if the app is called from servers.

## Anonymous users

Turn on **Allow anonymous users** to let visitors chat without signing in. The [chat widget](/docs/widget/) then creates an anonymous user per browser on its own. Anonymous access needs at least one allowed origin. See [anonymous users](/docs/auth/anonymous/).

## API keys

Your backend uses an app's API key to [issue tokens](/docs/auth/issue-tokens/) for your signed-in users. In **Apps**, click the app and choose **New API key**. The key is shown once: keep it on your servers.

From the same place you can update a key's expiration, roll it (a new secret replaces the old one right away) or delete it.

To try a key, open the app's menu and choose **Generate token**. It issues a token for a test user, the same call your backend makes, and shows the widget snippet to use it.

## One app or several

Use one app per product or site. Separate apps keep their users, conversations and keys apart, so a key leaked from one can't act on another.
