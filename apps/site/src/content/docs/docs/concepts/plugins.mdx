A plugin is an integration with an external service, like GitHub, Linear or Stripe. Each one brings **tools** an agent can call: search issues, create a customer, read the docs.

## Catalog and connections

**Plugins** lists the catalog. To use a plugin, add a **connection** to it: a named instance with its own credentials. Two GitHub connections with different tokens are two connections of the same plugin.

![Plugin catalog](/images/docs/plugins-catalog.png)

When you save a connection, Snipet fetches the plugin's tools and keeps them in sync. Credentials are stored encrypted. A tool the plugin gains in a later sync stays off for agents that already use the connection, until you [turn it on](/docs/concepts/agents/#plugins) in the agent.

The catalog has:

- **Code and docs**: GitHub, GitMCP, DeepWiki, Context7, Hugging Face, Microsoft Learn, AWS Knowledge, Cloudflare Docs.
- **Web search and scraping**: Exa, Tavily, Firecrawl, Apify.
- **Work and data**: Linear, Stripe, Supabase, Neon.
- **Debugging**: Debug (disk) and Debug (S3), see [hooks](#hooks).
- **Any MCP server**: see [below](#any-mcp-server).

![Plugin connection form](/images/docs/plugins-connection-form.png)

## Instructions

Many plugins come with instructions that tell the model how to use their tools well. Snipet adds them to the prompt of every agent allowed to use the connection. Write your own instructions on the connection to replace them, for example to point the agent at the repositories that matter.

## Hooks

Some plugins act on the run itself instead of offering tools: they hook into moments of the agent loop, like before each model call or each tool call, and can change what goes through, block a tool call, answer in the model's place or stop the run. The connection form shows what each of its hooks can do.

- **Debug (disk)** and **Debug (S3)** save every event of the agent's runs as a JSON file, in a directory of the API server or in an S3 bucket, to inspect what goes in and out. The files hold whole conversations: add them only while debugging.

## Any MCP server

The **MCP** plugin connects to any server that speaks the [Model Context Protocol](https://modelcontextprotocol.io) by URL. Its tools work like any other plugin's.

## Your own plugins

Plugins are JSON manifests, each listing its `capabilities`: `tools`, `instructions` and `hooks`. Put your own in the folder set by `PLUGINS_DIR` and they show up in the catalog. With the Docker setup, that's the `./plugins` folder next to `docker-compose.yml`.
